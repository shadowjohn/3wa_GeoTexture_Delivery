# 批次產製第一階段結果

依照 [技術評估](2026-11-06-optimization-review.md) 的第一優先項，PHP worker 現在每批共用一個 Python 行程，以有大小限制的 NDJSON 逐棟傳入凍結資料、逐棟完成登錄並更新進度。每棟產製仍有 20 秒上限；程序錯誤會關閉並回收子程序，下一棟可重新啟動。

逐棟登錄只重算受影響任務的 SQL 計數，不再重掃全部成果。每批開始和詳細任務讀取仍核對既有成果；登錄、下載、匯出保留完整性驗證。重疊任務若已由前一筆成果滿足，就跳過該筆，避免重複生成。

程序化任務不再寫入 `db/inputs/*.json`；實景前置資料和單檔 Python/PHP CLI 保留原有行為。既有 JSON、模型、來源資料與密碼未刪除或遷移。仍使用既有 cron、SQLite 與 `flock`，沒有增加服務或套件。

## 完整 worker 實測

2026-11-06，同一主機、同一 SQLite 快照（8 個任務、14,060 筆項目、4,611 份既有成果）。兩份私有測試狀態共用既有模型的 hard link，各自產生新成果；來源資料庫唯讀，正式排程繼續執行。指定同一個待處理的台灣街區任務，依既有順序處理前 20 棟，無批次時間限制。

這組樣本耗時減少約 94.6%，約快 18.6 倍。20 棟的來源版本、風格與 GLB SHA-256 全部一致。RSS 是工具回報的單一程序最大值，不是 PHP 與 Python 的同時總用量。

這是單次、先舊後新的有限樣本，含完整登錄與每批初始核對，未承諾所有範圍、風格或主機都有相同倍數。每批仍全量核對一次；既有成果持續增加時，這段成本仍會增長。此階段尚未改變 GLB primitive 數或瀏覽器的 GPU 負擔。
