# 同材質繪製單元合併結果

[批次產製](2026-11-06-batch-results.md) 之後，完成優先順序第二項：每棟程序化 GLB 按外牆、屋頂、底面合成三個 primitive。同一材質的三角形放在一起，每面仍以 `extras.surface_ranges` 保留原本 key 與索引範圍。manifest 的逐面來源、面積和覆蓋率不變。

PHP 對新的 ranges 檢查完整覆蓋、正值、連續、無重疊、無越界及三角形邊界，再用對應的真實三角形計算每面面積。單純把 manifest／SHA 改成相符不能繞過幾何核對；既有 `wall_key`／`surface_key` 格式繼續支援。

## 同一組實際建物

取任務中依 rowid 排序的前 100 棟台灣街區建物，以改版前後程式產生獨立暫存模型。

| 項目 | 改版前 | 改版後 |
| --- | ---: | ---: |
| 每棟 primitive 最少／中位數／最多 | 6／11／58 | 3／3／3 |
| 100 棟 primitive 合計 | 1,363 | 300 |
| GLB 總大小 | 3,151,612 bytes | 2,198,684 bytes |

檔案總量減少約 30.2%。逐面展開後，100 棟所有索引指向的頂點位置、法線、UV 與內嵌 PNG SHA-256 完全一致。配方 key 不變，外觀規則沒有改版；只是改變相容三角形的儲存分組。

## 瀏覽器核對

以 Chromium headless／SwiftShader、現有預覽器相同的 Three.js 0.178、光源與固定相機，依序單獨載入前 20 棟的舊／新模型。每次只有一棟模型，沒有地圖或格線；從 `renderer.info` 讀取實際繪製次數。

| 項目 | 改版前 | 改版後 |
| --- | ---: | ---: |
| 20 棟各一次繪製的 Draw Call 合計 | 267 | 60 |
| 單棟 Draw Call 中位數 | 12.5 | 3 |
| 單棟三角形數中位數 | 38 | 38 |
| 單棟 GPU 紋理數 | 2 | 2 |
| 載入至首次繪製時間中位數 | 246.85 ms | 228.35 ms |

Draw Call 減少約 77.5%。100 棟中原本 58 個 primitive 的代表建物，固定視角 900×700 畫面比較 630,000 個像素，全部相同。此量測只代表固定模型場景與軟體繪圖環境，不代表完整 E8 地圖、手機或實體 GPU 的 FPS／顯存提升。貼圖數尚未減少，共用圖集與分塊是下一個優先項。

## 測試與更新範圍

- Python 32 tests、64 subtests：三種風格 × 普通、凹形、中庭、MultiPolygon、反向輪廓的舊輸出快照，批次／單檔一致性及既有照片 GLB 測試。
- PHP app 116 checks、procedural 登錄／匯出、batch worker、HTTP 整合。新測試包含 malformed ranges、重算 hash 後的越界／缺段／重疊／非整數與合法分段但面積不符的拒絕，以及舊格式接受。
- 既有成果保留；新生成或重新轉換的模型採用合併格式。沒有為更新排程批量重做已完成的模型，也沒有改變使用者風格選擇。

共用圖集、分塊預覽、整區 GLB、外觀 v2 與可信實景校準仍屬後續工作，未在這次幾何分組中混入。
